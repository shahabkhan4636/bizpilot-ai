## Decisions worth not re-litigating

- **Postgres in production, never SQLite on Vercel.** `src/lib/db.ts` picks the engine from
  `DATABASE_URL`; `scripts/db-migrate.mjs` selects the engine-specific migration variant.
- **One query surface for both engines.** `all/get/run/one` behave identically; `?` placeholders are
  rewritten for Postgres by `src/lib/pg-sync.ts`, which also asserts placeholder/parameter counts.
- **Migrations are the only schema path.** `sql/migrations/NNN_name.{up,down}.{sql,postgres.sql,sqlite.sql}`,
  with `sql/schema.sqlite.sql` generated by `npm run db:schema` (CI check: `node scripts/build-schema.mjs --check`).
  `--baseline` exists for databases created from the snapshot; it must never be used to skip a
  migration whose effect you have not applied.
- **Server actions are the security boundary.** Permission checks live in `src/lib/actions/*`, not in
  the UI. The UI hides what the role cannot do, which is convenience only.
- **Denials are visible.** `ForbiddenError` → inline form error; void actions → `/forbidden`.
- **Money is integer cents, computed in one pure function** (`src/lib/proposal-math.ts`):
  subtotal → discount → taxable → tax → total, all clamped, never negative.
- **Provider absence is a first-class state.** Stripe, Resend, AI and Dropbox each have an explicit
  "not configured" surface plus a readiness warning. Nothing fakes a success.
- **Human approval gate stays.** Automation emails are queued for approval, never sent silently.

## Known limits / next up

1. **Live provider verification is BLOCKED** without credentials: Stripe checkout + webhooks, Resend
   delivery, AI generation, Dropbox storage, production `DATABASE_URL`, Vercel deploy. Each has a
   documented setup path in `.env.example` and a readiness warning; none is marked done.
2. **CSP is nonce-based for scripts; `style-src` still allows `'unsafe-inline'`** because CSP has no
   nonce mechanism for inline style attributes (chart geometry). The consequence of the nonce policy
   is that every route renders dynamically — static marketing pages are no longer prerendered. If
   that ever matters for edge caching, the alternative is a per-route policy and a maintained
   allowlist of prerendered routes.
3. Time-based automations need `CRON_SECRET` and a scheduler hitting
   `/api/cron/automations`; event triggers work without it and the page says so.
4. Dropbox is connected per workspace through OAuth (`DROPBOX_APP_KEY`/`DROPBOX_APP_SECRET`);
   `DROPBOX_ACCESS_TOKEN` remains a single-tenant fallback. Live OAuth is **BLOCKED** here (no app keys).
5. Playwright must run the whole file: the suite is serial and resets the database in `beforeAll`,
   so `-g` on a later test will fail on missing seed users by design.
6. `data/bizpilot.db` is dev-only local state and is safe to delete; migrations recreate it.
7. Rotate leaked tokens: GitHub `ghp_a5a6…`, Netlify `nfp_7CWU…`.
8. AI spend is tracked from the provider's own token counts (`src/lib/ai-usage.ts`). Cost stays
   "not priced" until `AI_PRICE_INPUT_PER_MTOK` / `AI_PRICE_OUTPUT_PER_MTOK` are set — `/api/readiness`
   warns about exactly that, on purpose.
9. Backups: `npm run db:backup` / `npm run db:restore` are verified for both engines (see
   `docs/BACKUP-AND-RESTORE.md`), but nothing schedules them — production needs a cron entry or the
   provider's own snapshots.
