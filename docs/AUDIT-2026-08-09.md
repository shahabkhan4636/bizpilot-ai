## 2. Method

1. Read the repository as it is: 160 files under `src/` (21k lines), 24 vitest files, 2
   Playwright specs, 9 migrations beyond the snapshot, `package.json`, configs, docs.
2. Cross-checked every documented claim against source. Documentation was not trusted.
3. Wrote throwaway analysis scripts for dead files and unused dependencies rather than
   deleting by filename (see §3).
4. Ran the suite, made one category of change at a time, re-ran the relevant gate.
5. Recorded rejected changes with the measurement that rejected them (§4.1).

### Checked and found clean (no change made)

- **No dead files.** Every non-route module under `src/` is imported by something; the
  analysis script reports zero orphans (route files are entry points by definition).
- **No dead scripts.** `migrate.mjs` (SQLite snapshot), `migrate-pg.mjs` (used by
  `npm run test:postgres`), `pg-worker.mjs` (the Postgres bridge process) are all live.
  Nothing was deleted on the assumption that its name looked redundant.
- **No `any`, no `@ts-ignore`, no `@ts-expect-error`, no TODO/FIXME/HACK** anywhere in
  `src/`, `tests/`, `scripts/` or `e2e/`.
- **No sensitive logging.** The only `console.*` calls are in `src/lib/logger.ts` (the
  single logging sink), one boot line in `pg-sync.ts`, and the two error boundaries.
  Every log line is structured JSON with no passwords, tokens or connection strings.
- **No string-built SQL from user input.** Every interpolation is a placeholder list
  built from a fixed allowlist (`fields.map(f => `${f} = ?`)`, `?,?,?`) or an identifier
  that came from `sqlite_master`/`information_schema`. `resetDatabaseForTests()` is the
  only place a table name is quoted, and it is test-only.
- **No `dangerouslySetInnerHTML`** except the theme bootstrap script in `layout.tsx`,
  which is a compile-time constant, carries the CSP nonce, and is asserted by e2e.
- **No N+1 queries.** No query is issued inside a loop anywhere in `src/`.
- **Indexes**: 41 indexes over 38 tables, including a composite
  `(organization_id, created_at)` on every tenant table and
  `email_outbox(status, next_attempt_at)` for the retry worker. Three indexes are
  declared twice in the schema snapshot (`leads_org_created_idx`,
  `leads_org_status_idx`, `organization_members_*`); it is `create index if not exists`,
  so this is cosmetic, and rewriting the snapshot to fix it would churn a file that is
  checksum-compared against the migrations. **Deliberately left alone.**

## 4. Rejected changes (and why)

### 4.1 Route-level `loading.tsx` skeletons — reverted

Phase 7 asks for loading states, and there are none: every route is dynamic. I added a
shared skeleton and 13 `loading.tsx` files, then measured.

`loading.tsx` wraps the page in a Suspense boundary whose shell is **flushed
immediately**. A `notFound()` or `redirect()` thrown *after* the shell is on the wire
can no longer set the HTTP status — the browser gets `200` and a client-side
navigation. Two Playwright tests caught it immediately:

```
Expected: 404   Received: 200   (e2e/app.spec.ts:287, /admin as a non-owner)
```

That status code is not cosmetic. The whole design of `/admin` is "a stranger gets the
same 404 as a URL that was never built" — a redirect or a 403 would confirm the admin
area exists. The same applies to `/suspended` and to anonymous hits on every guarded
page. A nicer first paint is not worth weakening an authorisation signal, so all 13
files and the component were removed. Fixing it properly means moving the guard ahead
of the Suspense boundary (a layout-level gate), which is a design change, not a
cleanup — **it belongs in a phase of its own, with the owner's sign-off.**

### 4.2 Deduplicating the schema snapshot

As above: `sql/schema.sqlite.sql` is generated (`npm run db:schema`) and
`--check`-compared, so hand-editing it is the wrong layer.

## 5. The two fixes in detail

### 5.1 One gate for every mutation

`src/lib/authz.ts` now owns the rule in one place:

```ts
export function assertImpersonationAllowsWrite(ctx: AuthContext, label: string): void
export async function requireWriteAuth(label: string): Promise<AuthContext>   // requireAuth + the gate
```

`requirePermission()` calls it for permission-based writes; every mutation that has no
permission now calls `requireWriteAuth("profile:password")`,
`requireWriteAuth("settings:workspace")`, `requireWriteAuth("billing:cancel")`,
`requireWriteAuth("team:invite")`, `requireWriteAuth("approval:act")`,
`requireWriteAuth("ai:generate")`, `requireWriteAuth("account:delete")` and so on. An
allowed write still records `impersonated_write: true` with that label, and the
workspace owner is still notified once per session.

Verified three ways:

1. `tests/authorization-gates.test.ts` — behaviour: refuses in read-only mode for five
   labels, records nothing, allows and audits in write mode, notifies once.
2. The same file — structure: every exported action in `src/lib/actions/*.ts` must call
   `requirePermission` / `requireWriteAuth` / `requireSuperAdmin`, directly or through a
   guarded local helper, unless it is on an explicit exemption list with a reason.
   Removing one gate makes the suite fail:
   `mutating actions with no authorisation guard: billing.ts:cancelSubscriptionAction`.
3. `e2e/admin.spec.ts` — the read-only session now also shows a "Read-only mode" notice
   on `/settings`, and the notice disappears when write mode is enabled.

The UI tells the same story: `/settings` and `/billing` show the read-only explanation
before the forms rather than failing after a submit, and the approval action returns a
sentence instead of a 500.

### 5.2 `/api/health` says nothing about customers

```json
{"ok":true,"engine":"sqlite","migrated":true,"tables":37,"plans":4,"latencyMs":0,"time":"…"}
```

`leads` is gone, and a database failure returns `{"error":"database unreachable"}` with
the real message in the server log (keyed by the request id the middleware adds).
`tests/health-probes.test.ts` asserts both, and asserts that health and readiness can no
longer disagree about the schema.
