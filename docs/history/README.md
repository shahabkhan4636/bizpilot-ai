# History — the audit trail

These documents are the record of how the project got here. They are kept because the
reasoning behind a decision is worth more than the decision, and because "why is this
code like this?" is usually answered in one of them.

They are **not** current instructions. Anything operational lives in:

| Need | Read |
| --- | --- |
| owner launch / deploy | [`../DEPLOY-ADMIN.md`](../../DEPLOY-ADMIN.md) |
| what the product does today | [`../../PROJECT-REPORT.md`](../../PROJECT-REPORT.md) |
| where the project stands | [`../../PROJECT_STATUS.md`](../../PROJECT_STATUS.md) |
| what changed when | [`../../CHANGELOG.md`](../../CHANGELOG.md) |

| File | What it is |
| --- | --- |
| `PHASE-REPORT.md` | Phase 0/1: the original architecture audit, feature inventory, bug/security/database/deploy assessment |
| `PHASE-2-REPORT.md` | Phase 2: PostgreSQL, versioned migrations, rollback, RLS verification |
| `PHASE-3-REPORT.md` | Phase 3: security and multi-tenant isolation, roles, denial handling |
| `PHASE-0-SETUP.md` | the platform-owner build-out plan that phases 1–6 were executed against |
| `HANDOFF.md` | working handoff notes from that period |
